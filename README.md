# Survivor Prototype

뱀파이어 서바이버즈 계열(서바이버라이크 / bullet heaven) 프로토타입.
**고양이 한 마리가 몰려오는 쥐떼를 상대한다.**

원작과 같은 기술 스택인 **Phaser 3 + TypeScript**로 만들었고, 디자인 에셋은
게임 로직과 완전히 분리해서 통째로 갈아끼울 수 있게 했다.

## 실행

```bash
npm install
```

```bash
npm run dev
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 (http://localhost:5173) |
| `npm run build` | 프로덕션 번들 (`dist/`) |
| `npm run typecheck` | 타입 검사만 |

## 조작

- **WASD / 방향키** — 이동 (공격은 전부 자동)
- **1 / 2 / 3 또는 클릭** — 레벨업 카드 선택
- **T** — 테마(디자인 에셋) 전환
- **ESC** — 일시정지 (현재 무기·패시브 확인, 이어하기 / 다시 시작)
- **Space / Enter** — 사망 후 재시작

## 고양이 테마 에셋

- 고양이와 쥐는 `idle` + 2프레임 걷기 텍스처를 사용한다. 이동 중에는 다리·앞발이 교대로 움직인다.
- 기본 무기 **털실 뭉치**는 고양이가 들고 있는 분홍 털실을 그대로 투사체로 쓴다.

테마는 `cats`(기본, 고양이 vs 쥐) / `neon` / `forest` 세 개가 들어 있고 T로 순환한다.
`?theme=neon` 쿼리로 특정 테마로 시작할 수도 있다.

## 구조

```
src/
  config.ts            밸런싱 상수 전부 (여기부터 만지면 된다)
  types.ts             공용 타입
  bus.ts               GameScene <-> UIScene 이벤트 버스
  data/
    enemies.ts         적 종류 테이블
    weapons.ts         무기 정의 (레벨 -> 스탯 함수)
    passives.ts        패시브 정의
  systems/
    SpatialHash.ts     충돌 브로드페이즈 (성능의 핵심)
    Pool.ts            오브젝트 풀
    Progression.ts     무기/패시브 보유 상태와 레벨업 선택지
  scenes/
    GameScene.ts       시뮬레이션 루프 전체
    UIScene.ts         HUD, 레벨업 카드, 게임오버
  theme/
    types.ts           ShapeSpec / Theme 정의
    themes.ts          << 디자인 에셋은 여기에 있다
    critters.ts        고양이/쥐/치즈/발톱을 코드로 그리는 함수
    textures.ts        도형 -> 런타임 텍스처 생성
```

## 디자인 에셋 교체하기

게임 코드는 **텍스처 키만 참조한다** (`TEX.player`, `TEX.enemy('grunt')` 등).
따라서 아트를 바꿔도 로직은 한 줄도 건드릴 필요가 없다.

### 1) 지금 상태 — 코드로 그린 스프라이트

`src/theme/themes.ts`의 `ShapeSpec`을 고치면 즉시 반영된다.

```ts
enemies: {
  grunt: { kind: 'mouse', size: 28, fill: 0x8e97a6, stroke: 0x2a2f38, strokeWidth: 2, accent: 0xf2b8c6 },
}
```

`kind`는 두 종류가 있다.

- **원시 도형** — `circle` `ring` `rect` `diamond` `triangle` `star`
- **캐릭터** — `cat` `mouse` `cheese` `claw` (`src/theme/critters.ts`에서 그린다)

캐릭터 도형은 좌표가 0~1 정규화라 `size`를 바꿔도 비율이 유지된다.
색은 `fill`(몸통) / `stroke`(외곽선) / `accent`(귀 안쪽·배) / `tail`(꼬리) 네 개로 변형을 만들고,
**쥐 4종은 전부 같은 `drawMouse`에 색과 크기만 다르게 준 것이다.**

고양이(니티)와 쥐(치지) 모두 캐릭터 디자인 시트를 따랐다.
둘은 같은 몸통 실루엣(`pearBody`)을 공유하고 **귀 모양 · 꼬리 · 줄무늬 · 들고 있는 아이템**으로 구분한다.

| | 고양이 (니티) | 쥐 (치지) |
| --- | --- | --- |
| 몸통 | `#CFC7BA` | `#9E948B` |
| 배 · 주둥이 | `#EADFCB` | `#F0E2C6` |
| 귀 안쪽 | `#FFCFA3` | `#F0E2C6` |
| 외곽선 | `#5E4B3C` | `#5A3E28` |
| 꼬리 | 몸통색 + 줄무늬 | `#A67C52` |
| 줄무늬 | `#8E7D6D` | — |
| 아이템 | 털실 `#F6A3B1` | 치즈 `#F9C77A` / `#D9B15B` |
| 귀 | **뾰족한 삼각** | **동그란 원** |

디자인 노트의 "단순한 실루엣으로 가독성 확보"에 맞춰 발과 다리는 생략했다.
쥐가 치즈를 안고 있는 모습(`holdsItem: true`)은 엘리트에만 줬다 — 이유는 아래 참고.

새 종류를 추가하려면 `critters.ts`에 그리는 함수를 만들고
`ShapeKind`와 `textures.ts`의 switch에 한 줄씩 추가하면 된다.

새 테마는 객체 하나를 더 만들어 `THEMES` 배열에 넣으면 된다 (첫 번째가 기본).

### 2) 실제 스프라이트로 교체

1. PNG를 `public/assets/` 아래에 둔다.
2. `Theme.images`에 텍스처 키 -> 경로를 매핑한다.

```ts
images: {
  'tex:player': 'assets/player.png',
  'tex:enemy:grunt': 'assets/slime.png',
}
```

3. 매핑된 키는 `buildTextures()`가 도형 생성을 건너뛴다.

적 스프라이트는 `EnemyKind.radius` 기준으로 자동 스케일되므로
원본 PNG 크기는 신경 쓰지 않아도 된다.

### 표시 크기 규칙

텍스처는 선명하게 하려고 표시 크기의 2배로 굽는다 (`SUPERSAMPLE`).
40px 고양이 얼굴을 그대로 그리면 눈·수염이 1px이라 뭉개지기 때문이다.
그래서 스프라이트 크기는 항상 `GameScene.scaleTo()`가
**현재 텍스처의 실제 폭**을 보고 맞춘다. 테마마다 텍스처 크기가 달라도,
그리고 실행 중에 테마를 바꿔도 표시 크기가 어긋나지 않는다.

- 적: `radius * 2 / bodyRatio`
- 플레이어/투사체/젬: 테마의 `size`
- 장판(aura): 무기의 유효 반경

`bodyRatio`는 텍스처 박스에서 **몸통이 차지하는 가로 비율**이다.
쥐는 꼬리와 귀가 몸 밖으로 뻗어서(몸통 0.56, 꼬리 끝 0.96), 박스를 히트박스 지름에
그대로 맞추면 정작 몸이 히트박스보다 훨씬 작아 보인다. 이 값을 주면
"몸통 폭 = 히트박스 지름"이 되도록 스프라이트를 키운다.
생략하면 1이라 도형 테마(`neon` / `forest`)는 예전처럼 박스 = 히트박스로 동작한다.

## 구현된 것

- 자동 공격 무기 4종 — 유도 투사체(샤드), 부채꼴 탄막(스캐터), 궤도체(오빗), 지속 장판(펄스)
- 무기별 8레벨 성장, 패시브 7종 5레벨
- 레벨업 시 3택 카드 (신규 무기 / 무기 강화 / 패시브)
- 경험치 젬 드랍 + 자력 흡수
- 시간에 따른 적 종류 해금과 능력치 스케일링, 90초마다 엘리트
- 무한 스크롤 필드, 카메라 추적
- 넉백, 피격 무적, 적 밀어내기(separation)
- 게임오버 / 재시작
- 테마(에셋) 런타임 교체

## 디자인 판단 두 가지

**일반 쥐는 치즈를 들지 않는다.** 시트의 시그니처지만, 이 게임에서는 치즈가
바닥에 떨어지는 경험치 아이템이다. 후반에 적 수백 마리가 전부 노란 치즈를 들고 있으면
주울 수 있는 치즈와 구분이 안 된다. 대신 엘리트에만 남겨서 "쥐 두목이 치즈를 챙겨 간다"는
읽기로 살렸다. `themes.ts`에서 `holdsItem: true`를 켜면 어느 쥐든 들게 할 수 있다.

**플레이어 발밑에 표식을 깐다.** 두 시트를 그대로 적용하면 고양이 `#CFC7BA`와
쥐 `#9E948B`가 둘 다 웜그레이라, 수십 마리에 둘러싸이는 순간 내 캐릭터를 못 찾는다.
실제로 화면으로 확인한 문제다.

시트 팔레트를 임의로 바꾸는 대신, 캐릭터의 시그니처 색(털실 분홍 `#F6A3B1`)으로
반투명 링을 하나 깔아 해결했다. 아트는 시트 그대로 두고 가독성만 얻는다.
표식은 적보다 위(`DEPTH.playerMarker = 15`), 플레이어보다 아래에 그린다.
도형 테마에서는 `hudAccent` 색을 쓴다.

뾰족한 귀(고양이) vs 동그란 귀(쥐)와 분홍 털실도 구분에 기여하지만,
20px 남짓으로 줄어들면 그것만으로는 부족하다.

## 성능

이 장르는 후반에 적이 수백~수천 마리 깔리기 때문에 충돌 판정이 전부다.
그래서 Phaser의 Arcade Physics를 쓰지 않고 직접 짰다.

- **공간 해시 그리드** (`SpatialHash.ts`) — 매 프레임 재구축, 질의는 주변 셀만 훑는다.
  순진하게 전수 비교하면 적 1000 x 투사체 200 = 프레임당 20만 회가 된다.
- **오브젝트 풀링** (`Pool.ts`) — 적/투사체/젬을 재사용해서 GC 스톨을 없앤다.
  풀 인덱스는 고정이라 공간 해시가 그 인덱스를 그대로 저장할 수 있다.
- **재사용 버퍼** — 질의 결과를 매번 새 배열에 담지 않는다.
- **separation은 프레임당 절반씩만** 처리한다. 눈으로는 차이가 없다.

측정값 (적 1284마리, 무기 4종 만렙, 렌더 제외 시뮬레이션 시간):

| | ms |
| --- | --- |
| median | 0.5 |
| p99 | 1.2 |
| max | 1.5 |

60fps 예산 16.67ms 대비 3~9% 수준이라 나머지는 렌더링에 쓸 수 있다.

## 밸런싱 메모

수치는 시뮬레이션으로 1차만 맞춰둔 상태다. **사람이 직접 해보고 조정해야 한다.**

- 스폰 예산은 "이벤트"가 아니라 **적 마릿수** 단위다.
  `swarm`처럼 무리로 나오는 적을 1로 계산하면 실제 스폰량이 3배로 튄다.
- 공격적으로 교전하며 도는 플레이에서는 적이 20~80마리로 유지되고
  5분에 13레벨 전후로 성장한다.
- 반대로 계속 도망만 다니면 적이 상한(900)까지 쌓이고 레벨이 거의 안 오른다.
  이 장르 특유의 실패 패턴이라 의도된 동작에 가깝지만, 초반 난이도는
  실제 플레이 감각으로 다시 볼 필요가 있다.
- 도망 다니면 젬이 바닥에 쌓인다. 풀이 가득 차면 가장 먼 젬을 재활용하고
  경험치는 합쳐서 소실을 막는다 (`farthestGem`).

밸런싱은 `src/config.ts`의 `difficultyScale()`과 `src/data/*.ts`에서 거의 다 조절된다.

## 법적 메모

게임 시스템(자동 공격, 경험치 수집, 레벨업 3택, 무리 스폰)은 저작권 대상이 아니다.
원작의 스프라이트, 음악, 이름, 캐릭터는 사용하지 않았고 에셋은 전부 코드로 생성한 도형이다.
실제 아트를 붙일 때도 직접 제작하거나 라이선스가 명확한 것만 쓰면 된다.
